## 📝 课程重点笔记

### 一、传输层概述

- 传输层位于 OSI 模型的第 4 层，是端到端（end-to-end）通信的关键层次
- 主要协议：**TCP**（传输控制协议）和 **UDP**（用户数据报协议）
- 核心功能：**复用/分用**（multiplexing/demultiplexing）

#### 端口号 [00:05:12]

- 源端口（16bit）+ 目的端口（16bit）= 32bit 的套接字标识
- 熟知端口（0-1023）：HTTP→80，HTTPS→443，FTP→21
- 注册端口（1024-49151）
- 动态/私有端口（49152-65535）

### 二、UDP 协议 [00:12:08]

| 特性 | 说明 |
|------|------|
| 无连接 | 发送前无需建立连接 |
| 不可靠 | 不保证送达、顺序、不重复 |
| 首部小 | 仅 8 字节 |
| 速度快 | 没有拥塞控制 |

#### UDP 首部格式
```
 0      7 8     15 16    23 24    31
+--------+--------+--------+--------+
|     源端口      |     目的端口     |
+--------+--------+--------+--------+
|     长度        |     校验和       |
+--------+--------+--------+--------+
```

- 典型应用：DNS、DHCP、视频流、在线游戏

### 三、TCP 协议

#### 3.1 TCP 特点 [00:22:35]

- **面向连接**：三次握手建立连接，四次挥手释放连接
- **可靠传输**：确认重传、序号机制
- **全双工通信**
- **面向字节流**
- **拥塞控制**：慢启动、拥塞避免、快重传、快恢复

#### 3.2 三次握手 [00:25:00]

```
Client                   Server
   |------SYN------>|       (1) 客户端发送 SYN=1, seq=x
   |<---SYN+ACK-----|       (2) 服务器回复 SYN=1, ACK=1, seq=y, ack=x+1
   |------ACK------>|       (3) 客户端发送 ACK=1, seq=x+1, ack=y+1
```

**为什么是三次握手？**
- 防止已失效的连接请求突然又传到服务器导致错误
- 双方确认各自的发送和接收能力正常

#### 3.3 TCP 流量控制 [00:33:17]

- 通过**滑动窗口**机制实现
- 接收方在 TCP 首部的 `window` 字段通告剩余缓冲区大小
- 发送方根据 `window` 大小调整发送量，避免接收方溢出

#### 3.4 TCP 拥塞控制 [00:41:50]

1. **慢启动**：指数增长，直到 ssthresh（慢启动阈值）
2. **拥塞避免**：线性增长（加性增）
3. **快重传**：收到 3 个冗余 ACK 立即重传，不等超时
4. **快恢复**：将 cwnd 减半而非降到 1

### 四、总结

- UDP：**快但不可靠**，适合实时应用
- TCP：**可靠但开销大**，适合网页、文件传输
- 理解三次握手的意义、滑动窗口和拥塞控制是面试常考内容 ⭐
